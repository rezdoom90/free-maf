# Multi-Agent Framework — Руководство пользователя

Multi-Agent Framework превращает обычный текстовый чат с бесплатной LLM (прежде всего — DeepSeek Expert) в командную работу с виртуальными профессионалами: аналитиком, планировщиком, разработчиком и контролёром качества. Встроенное приложение File Parser GUI позволяет парой кликов упаковать любые файлы проекта в текстовое представление и вставить их прямо в диалог — вы обходите главное ограничение бесплатных веб-интерфейсов и даёте агенту полный контекст вашей кодовой базы.

---

## Установка и настройка

Для развертывания фреймворка в новом или существующем проекте выполните следующие шаги:

1. **Скачайте фреймворк:** Нажмите кнопку `<> Code` (справа вверху репозитория) и выберите **Download ZIP**.
2. **Подготовьте директорию:** В корне вашего проекта создайте папку `agent`.
3. **Распакуйте архив:** Внутри ZIP-архива находится папка `ai-framework-main` (или с названием другой ветки). Извлеките всё её **содержимое** в созданную папку `agent`. В результате в `agent/` должны оказаться подпапки `rules`, `project`, `util` и файлы `file_parser_app.py`, `build_exe.bat` и т.д.
4. **Сгенерируйте карту проекта:** Запустите `agent/util/update_map.bat`. Это создаст (или обновит) `agent/project/MAP.md` — обязательный источник информации о структуре проекта для агента.
5. **(Опционально) Настройте File Parser GUI:** Сборка автономного .exe — запустите `agent/build_exe.bat`. Он сам проверит Python и при необходимости установит PyInstaller, после чего в `agent/` появится `FileParserGui.exe`. Готовый .exe запускается обычным двойным кликом или консольной командой `./agent/FileParserGui.exe` из корня вашего проекта.

## 1. Как начать работу

Эти наборы можно скопировать одним нажатием кнопок **Kick-off (New)** / **Kick-off (Existing)** в File Parser GUI.

### Сценарий А: Новый проект (с нуля)
1. **Kick-off:** Откройте новый чат. Нажмите **Kick-off (New)** в File Parser GUI — в буфер обмена скопируются `GENERAL_RULES.md` и `ANALYST_RULES.md`. Вставьте содержимое в чат и допишите: `start kick-off`.
2. **Интервью и аудит:** Аналитик проведёт интервью, прояснит цели, доступные инструменты и ограничения.
3. **Передача Планировщику:** По завершении интервью Аналитик сформулирует готовую цель. Передайте её Планировщику с командой «составь план».

### Сценарий Б: Внедрение в существующий проект
1. **Инициализация:** Отметьте в дереве File Parser GUI основные файлы проекта (исходный код, конфигурацию, любые файлы, описывающие проект), нажмите **Kick-off (Existing)** — в буфер обмена скопируются `GENERAL_RULES.md`, `ANALYST_RULES.md`, `MAP.md` (сгенерируется автоматически) и отмеченные файлы. Вставьте скопированное в чат и дайте краткое текстовое описание проекта и/или цели.
2. **Аудит:** Аналитик изучает предоставленные файлы, проводит аудит, при необходимости запрашивает у пользователя недостающие файлы, строит `PROJECT_STATE.md` (и `INFRASTRUCTURE.md` при необходимости), а затем предлагает пользователю сформулировать конкретную задачу по развитию проекта.
3. **Передача Планировщику:** Передайте сформулированную Аналитиком задачу Планировщику с командой «составь план».

## 2. Рабочий цикл (Chat Workflow)

Ваше общение с агентом проходит через четыре этапа (от анализа до проверки) с участием вспомогательной роли Web-Analyst.

### Этап 0: Анализ и аудит (Роль: ANALYST)
*   **Задача:** Прояснить и сформулировать цель, провести аудит проекта или предметной области.
*   **Когда нужен:** Перед планированием, если цель неясна, проект новый или требуется предварительный анализ.
*   **Ваше действие:** Нажмите **Analyst** в File Parser GUI — в буфер обмена скопируются `GENERAL_RULES.md`, `ANALYST_RULES.md`, `INFRASTRUCTURE.md`, `PROJECT_STATE.md`, `MAP.md` и выбранные файлы. Вставьте в чат и опишите, что нужно проанализировать или сформулируйте начальную цель.
*   **Финал этапа:** Аналитик выдаст отчёт `RESULT.md` с готовой формулировкой задачи. Передайте её Планировщику.

### Вспомогательная роль: WEB_ANALYST
*   **Задача:** Поиск информации в интернете по запросу любого другого агента.
*   **Как работает:** Если агенту нужны данные из сети, он сгенерирует `QUERY.md`. Нажмите **Web-Analyst** в File Parser GUI, вставьте скопированные файлы и содержимое `QUERY.md` в новый чат. Web-Analyst выполнит поиск, вернёт результат — передайте его запросившему агенту.

### Этап 1: Планирование (Роль: PLANNER)
*   **Задача:** Превратить готовую цель в список атомарных шагов.
*   **Ваше действие:** Нажмите **Planner** в File Parser GUI — в буфер обмена скопируются `GENERAL_RULES.md`, `PLANNER_RULES.md`, `MAP.md`, `PROJECT_STATE.md`, `INFRASTRUCTURE.md` и выбранные файлы проекта. Вставьте в новый чат, вставьте готовую задачу (от Аналитика или свою) и добавьте: `Составь план`.
*   **Финал этапа:** Вы внимательно прочли содержимое `PLAN.md` и запросили необходимые правки/уточнения, либо, если план вас полностью устраивает, сохранили его в `agent\project\PLAN.md`.

### Этап 2: Исполнение (Роль: EXECUTOR)
*   **Задача:** Выполнить `PLAN.md`.
*   **Важное условие:** Исполнитель следует правилу `PLAN_FIRST` — работа не начнётся, если в `agent/project` отсутствует `PLAN.md`. Убедитесь, что план загружен в `agent/project/PLAN.md`.
*   **Ваше действие:** Нажмите **Executor** в File Parser GUI — в буфер обмена скопируются `GENERAL_RULES.md`, `EXECUTOR_RULES.md`, `PLAN.md`, `MAP.md`, `PROJECT_STATE.md`, `INFRASTRUCTURE.md` и выбранные файлы проекта. Вставьте в новый чат и добавьте: `Начинай работу по плану` (новый запуск) или `Продолжи работу` (если уже есть `WIP.md` с прогрессом).
*   **Финал этапа:** Как только применили код, напишите "Код применен" — агент обновит статус `WIP.md`, и вам нужно будет обновить содержимое данного файла (высылать его в каждом сообщении не нужно, агент запомнит его содержание и правки, которые он сделал в рамках текущего чата).

### Этап 3: Проверка (Роль: JUDGE)
*   **Задача:** Строгая оценка результатов без права предлагать решения или генерировать код.
*   **Формат ответа:** Судья выводит JSON-объект с ключами `verdict` (PASS/REJECT), `score` (процент выполнения) и `flags` (массив оценок по каждому критерию) в ограждённом блоке `json`. Никакого текста вне этого блока.
*   **Ваше действие:** Нажмите **Judge Executor** (для оценки кода) или **Judge Plan** (для оценки плана) в File Parser GUI. Вставьте скопированное в новый чат и добавьте: `Проверь работу`. Если изменённых файлов больше 10, предупредите агента, что отправляете их в несколько этапов — он дождётся последнего.
*   **Финал этапа:** При `score >= 80%` выносится вердикт PASS — работа принята. При `score < 80%` — REJECT с перечнем несданных критериев; правки вносит исполнитель, судья их не предлагает.

### Краткий пример (DeepSeek Expert)

0. **Анализ:** Analyst → вставить → описать задачу (например: «проведи аудит слоя работы с БД») → получить `RESULT.md` с выводами и готовой формулировкой цели для Планировщика.
1. **План:** Planner → вставить → `Составь план по задаче: <цель из RESULT.md>` → сохранить в `agent/project/PLAN.md`.
2. **Проверка плана:** Judge Plan → вставить → `Проверь работу планировщика`. При REJECT — вернуться к п.1.
3. **Исполнение:** Executor → вставить → `начинай работу по плану`. Применить код.
4. **Проверка результата:** Judge Executor → вставить → `проверь работу исполнителя`. При REJECT — вернуться к п.3.

### Рекомендации по выбору модели ИИ

| Модель | Рекомендуемые задачи | Примечания |
|---|---|---|
| **DeepSeek Expert (MoE)** | Тяжеловесная работа с кодом, большие объёмы данных/текста, планирование (Planner), исполнение (Executor) | Основная рабочая лошадка фреймворка для сложных задач. |
| **Gemini Pro** | Лёгкие задачи и приложения, веб-аналитика (Web-Analyst: поиск и верификация ссылок) | Хороший баланс скорости и качества для вспомогательных ролей. |
| **DeepSeek Instant** | Только веб-аналитика (Web-Analyst: быстрый поиск) | Минимальная задержка, подходит для простых поисковых запросов. |

> **Важно:** Если задача не решается после 3 попыток (разных подходов) на текущей модели — переключитесь на более мощную модель. См. правило `MODEL_SWITCH_ESCALATION` в GENERAL_RULES.md.

## File Parser GUI

Легковесное Tkinter-приложение, которое отображает дерево файлов проекта с чекбоксами и предоставляет кнопки пресетов для копирования обязательных файлов правил агента вместе с выбранными пользователем файлами в системный буфер обмена в структурированном формате `<file name="...">...</file>`.

### Запуск
- Дважды кликните `agent/run_file_parser.bat` (Windows) или
- Запустите из терминала: `python agent/file_parser_app.py`

### Как использовать
1. В левой панели отметьте файлы, которые хотите включить.
2. Нажмите одну из кнопок ролей справа:
   - **Kick-off (New)** – `GENERAL_RULES.md` + `ANALYST_RULES.md` (интервью с Аналитиком для нового проекта).
   - **Kick-off (Existing)** – `GENERAL_RULES.md` + `ANALYST_RULES.md` + `MAP.md` (PROJECT_STATE.md и INFRASTRUCTURE.md не включаются — Аналитик создаст их при аудите).
   - **Analyst** – `GENERAL_RULES.md` + `ANALYST_RULES.md` + `MAP.md`. `PROJECT_STATE.md` и `INFRASTRUCTURE.md` прикрепляются только если существуют; при их отсутствии Аналитик считает проект новым для фреймворка.
   - **Web-Analyst** – `GENERAL_RULES.md` + `WEB_ANALYST_RULES.md` + `QUERY.md`. Если `QUERY.md` отсутствует, копируются только правила. Без `QUERY.md` и без задачи от пользователя Web-Analyst сообщит о необходимости прикрепить запрос.
   - **Planner** – `GENERAL_RULES.md` + `PLANNER_RULES.md` + `MAP.md`. `PROJECT_STATE.md` и `INFRASTRUCTURE.md` прикрепляются только если существуют.
   - **Executor** – `GENERAL_RULES.md` + `EXECUTOR_RULES.md` + `PLAN.md` + `MAP.md`. `PROJECT_STATE.md` и `INFRASTRUCTURE.md` прикрепляются только если существуют.
   - **Judge Plan** – `GENERAL_RULES.md` + `JUDGE_RULES.md` + `PLAN.md` + `MAP.md`. `PROJECT_STATE.md` и `INFRASTRUCTURE.md` прикрепляются только если существуют.
   - **Judge Master Plan** – `GENERAL_RULES.md` + `JUDGE_RULES.md` + `MASTER_PLAN.md` + `MAP.md`. `PROJECT_STATE.md` и `INFRASTRUCTURE.md` прикрепляются только если существуют.
   - **Judge Executor** – `GENERAL_RULES.md` + `JUDGE_RULES.md` + `PLAN.md` + `MAP.md`. `PROJECT_STATE.md` и `INFRASTRUCTURE.md` прикрепляются только если существуют.
   - **Get MAP.md** – регенерирует и копирует только `MAP.md` (не зависит от выбранных файлов).
   - **Get Files** – копирует только отмеченные файлы, без `MAP.md`.
   - **Get Files + MAP.md** – копирует отмеченные файлы + авторегенерированный `MAP.md`.
3. Для ролевых кнопок обязательные файлы (правила, состояние, инфраструктура, карта) копируются вместе с выбранными вами файлами. Кнопки **Get Files** и **Get Files + MAP.md** работают только с ручной выборкой.
4. **Clear** снимает все отметки; **All** выбирает всё.
5. Перед копированием кнопки, требующие `MAP.md`, автоматически перегенерируют его.

### Запуск .py скрипта без компиляции
Если Python уже установлен, вы можете запустить File Parser GUI напрямую, без сборки .exe:
1. Установите зависимость: `pip install pyperclip`
2. Запустите скрипт командой: `python agent/file_parser_app.py`

### Сборка автономного .exe
1. Дважды кликните `build_exe.bat` в папке `agent/`.
2. Дождитесь завершения сборки.
3. Запустите `FileParserGui.exe` из папки `agent/`.

### Структура директорий (v4.6)
- `agent/rules/` — правила ролей (`GENERAL_RULES.md`, `PLANNER_RULES.md`, `EXECUTOR_RULES.md`, `JUDGE_RULES.md`, `ANALYST_RULES.md`, `WEB_ANALYST_RULES.md`).
- `agent/project/` — артефакты проекта (`MAP.md`, `PLAN.md`, `MASTER_PLAN.md`, `PROJECT_STATE.md`, `INFRASTRUCTURE.md`, `WIP.md`).
- `agent/util/` — вспомогательные скрипты (`generate_map.ps1`, `update_map.bat`).
